# OpenList TV 实施架构

当前：1.0.0，已完成负责人实测验收。本文说明项目架构与资源约束。

当前工作分支的 1.0.1 增量见 [本地迭代上下文](DEVELOPMENT_1.0.1.md)：GitHub 检测、原生 HDR 与 128 MiB 图片输入。下面保留 1.0.0 基线；新分支暂不对外发布。

## 依赖方向

`app` 负责组合与原生 TV 界面，依赖 `core`、`data`、`media`。`data` 与 `media` 只依赖 `core`，互不依赖。没有自建服务端、NDK、WebView 或跨平台引擎。

- `core`：纯 Kotlin 模型、路径/自然排序、认证与文件访问接口、轮播策略接口、资源预算及有界历史。
- `data`：OpenList 适配、严格检查 HTTP/业务码、用户根路径、SQLite 有界目录索引、加密会话、站点隔离。
- `media`：单 ExoPlayer、HLS、硬件视频解码选择、已有低清轨道降级、HDR 拒绝、串行采样图片解码。
- `app`：原生 View/RecyclerView、D-pad、登录/浏览/设置、独立轮播会话和暂停/恢复。应用生命周期内只有一个 Catalog 数据库连接管理器。

## 扩展点

认证通过 `AuthProvider`，一期只实现本地账号密码。新增认证方式不得混入文件列表或播放器。

轮播通过 `TraversalSource` 与 `DirectoryReader`。顺序、随机游走策略属于 core；全树随机的扫描队列与媒体池落在 SQLite，扫描状态与播放计时分开。新增策略只添加实现和组合注册，不改网络请求或播放器。

媒体地址从 `/api/fs/get` 按需解析，不依赖管理员 `/api/fs/link`，也不重复拼接用户 `base_path`。API 与媒体使用隔离客户端；媒体重定向逐跳删除 Authorization/Cookie 等凭证，HTTP 必须按站点明确允许。

## 资源边界

目录每次网络请求最多 100 条；完整排序在 SQLite 中完成。RecyclerView 连续滚动，只保留当前页和下一页的元数据与缩略图窗口（每页 100 条）；越过边界再加载后续页，旧页退出窗口。全目录排序的元数据索引不等于全目录图片下载。索引全局最多 10 万记录、64 MiB。单个视频总大小不计入内存占用判断。

浏览缩略图优先使用 OpenList `thumb`，最多 2 个并发任务，按可见项优先，解码上限约 16,000 像素/图，8 MiB 位图 LRU、16 MiB PNG 磁盘缓存。没有有效服务端预览时，仅为可见项串行下载/采样原图（单张临时文件最多 32 MiB），不预抓下一页原图。请求遵守媒体凭证隔离和站点 HTTP 设置。进入播放器或后台时取消任务并释放列表位图；离开目录清理该窗口缓存，进程重启清理遗留临时预览。低内存解码失败只停止预览，不反复重试耗尽内存。

缩略图完成直接更新可见 ImageView，不触发整行数据重排；列表使用稳定行 ID 和显式上下焦点移动，避免连续遥控时异步预览更新夺走焦点。界面参考旧 AlistClient 的蓝色 Material 配色、圆角缩略图、清爽列表和系统深浅色；轮播输入框始终绘制字段名称、数值、秒单位，已有值不遮住提示。

音视频同一时刻一个播放器，网络样本缓冲目标 24 MiB，无后台服务和本地转码。图片临时文件最多 32 MiB，先读尺寸，再按屏幕与可用堆内存采样；最高 4K SDR，预留方向转换副本与解码临时空间。

alpha03 图片轮播采用“当前画面＋单项预加载”机制。当前图片显示后自动选择下一项；若也是图片，则下载并采样解码到 `OneAhead` 的唯一槽位，音视频仍只按原开关预取地址。切换在 UI 线程直接替换 ImageView 的 BitmapDrawable，不先清空、不显示“正在读取资源/准备下一项”。下一张晚到则保留当前图，停留计时从新图实际交付显示后重新开始；坏图可以跳过，鉴权/限流等全局错误仍明确暂停提示。

双图目标预算为 `min(64 MiB, JVM maxHeap / 4)`，每张最多占一半；可用内存还按原有解码临时空间规则再限制。解码串行、只预加载下一张，不构造图片队列。已显示位图交由 API 23+ 的 GC/HWUI 生命周期管理，避免在旧帧仍引用时强行 recycle；未显示的预加载位图则在取消/替换/退出时显式回收。该目标不包含所有系统 GPU/解码缓冲，也不是总 PSS 保证。

`OneAhead` 不让预加载异常直接取消播放会话：异常在轮到该项时消费；完成但未取走的图片仍由槽位拥有并可回收。前后历史使用无副作用 peek，随机模式的下一项保留为 Entry 预约；取消预加载不丢弃该预约。ImagePipeline 在跨 IO dispatcher 返回时保留临时所有权，防止取消丢弃已解码结果；暂停/后台/内存压力时取消未显示图片，慢加载暂停时继续保留已显示画面。旧的 `slide.prefetch` 字段保留为音视频地址开关，关闭它也不会关闭本次要求的图片自动预加载。

无低清源且无法解码：轮播跳过，连续失败暂停；手动点播显示错误。鉴权失效、限流和持续网络故障不冒充大量坏文件快速跳过。

## 覆盖升级契约

包名保持 `io.github.loliwolf.openlisttv`，versionCode 递增。alpha02 延续 alpha01 签名，构建前比较 `gradle/alpha-certificate.sha256`，签名不符即停止。公钥指纹可入库，私钥/口令不得提交；维护原签名密钥是后续升级的必要条件。发布渠道或签名迁移须单独设计，不能要求用户卸载来掩盖不兼容。

SharedPreferences 名称/字段及 Keystore alias 保持不变；SQLite v1→v2 仅增加 thumbnail 列，不删表重建。清缓存和原身份重连不清播放进度；显式退出账号，或将既有站点编辑为不同账号/服务器时，清理原身份历史，避免跨账号串用。网络暂不可用不抹除已保存站点或令牌。正常同包名、同签名覆盖安装保留配置；用户卸载、清应用数据或服务端撤销令牌不属于此保证。旧 Flutter AlistClient 与本原生应用之间不自动导入配置，这是不同于本项目版本升级的边界。

## 验证层次

JVM 测试覆盖自然排序、路径、历史、图片预算、协议业务码、密码哈希和重定向凭证隔离。Android 仪器测试覆盖 SQLite 跨页排序与随机轮次。`tools/mock-openlist.mjs` 是仅监听本机的合同测试服务，图片/音频均程序生成，不是生产 OpenList。

1.0.0 采用受保护存储的连续性签名，操作见 BUILDING.md；自有代码许可证未指定，知识库公开权限不擅自扩大。
